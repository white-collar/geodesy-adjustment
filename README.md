# Уравнивание геодезической сети

Веб-сервис для параметрического уравнивания плановых (2D) геодезических сетей методом наименьших квадратов. Работающий экземпляр: https://geo-adjust.onrender.com/

Вводятся опорные точки (с известными координатами) и измерения; приближённые координаты остальных точек вычисляются автоматически по цепочке измерений. На выходе — уравненные координаты, оценка точности (σ₀, эллипсы ошибок), невязки и, по желанию, подробный пошаговый журнал вычислений с матрицами A, N, b.

## Возможности

- Типы измерений: `distance`, `azimuth`, `angle`, `direction` (с неизвестной ориентировкой лимба на станции).
- Свободные и недоопределённые сети (через псевдообратную матрицу): если опорных точек недостаточно, результат помечается дефектом ранга.
- Загрузка всей сети одним YAML-файлом (опорные точки, измерения, служебная информация).
- Журнал вычислений: приближённые координаты, на каждой итерации матрицы A, N, b и поправки δ, итоговые невязки.

Ограничения: только 2D; точка, определяемая лишь засечкой (пересечением лучей или окружностей без цепочки измерений от опорных точек), пока не поддерживается и возвращает ошибку.

## Структура проекта

```
geo_adjust/   ядро: геометрия, солвер, оценка точности, предвычисление координат (без веб-зависимостей)
api/          FastAPI: POST /adjust, перевод единиц, раздача web/
web/          интерфейс (HTML/CSS/JS без сборки)
tests/        тесты (pytest)
examples/     примеры сетей в YAML
render.yaml   описание сервиса для Render
```

## Запуск локально

Нужен Python 3. Проект разрабатывался и проверялся на 3.14 (версия закреплена в `.python-version`); на более старых версиях не проверялся.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

uvicorn api.main:app --reload
```

Интерфейс откроется на http://127.0.0.1:8000/ , интерактивная документация API — на http://127.0.0.1:8000/docs .

Тесты (запускать из корня проекта):

```bash
python -m pytest tests/ -v
```

`requirements.txt` содержит только то, что нужно работающему приложению; `requirements-dev.txt` добавляет к нему `pytest` и `httpx`.

## Формат входного YAML

Пример: [examples/sample-network.yml](examples/sample-network.yml). Файл загружается кнопкой «Загрузить сеть (.yml)».

```yaml
meta:                      # произвольные пары ключ: значение
  project: Съёмка участка №14
  date: 2026-09-13
  executor: Иванов И.И.

defaults:                  # σ по умолчанию для измерений без своего sigma
  sigma_distance: 0.005    # метры
  sigma_angular: 0.6       # угловые секунды

reference_points:
  - {id: A, x: 0.0, y: 0.0}
  - {id: B, x: 0.0, y: 1000.0}

observations:
  - {type: distance, from: A, to: C, value: 854.4004}
  - {type: angle, from: A, to: B, to2: C, value: -69.443955}
  - {type: direction, from: D, to: E, value: 134.301409, sigma: 0.3}
```

Единицы: `distance` и `sigma` расстояний — метры; `value` для `azimuth`/`angle`/`direction` — градусы; `sigma` угловых измерений — угловые секунды. Оси: X — север, Y — восток, дирекционные углы отсчитываются от X по часовой стрелке. Все пункты, встречающиеся только в измерениях, считаются определяемыми.

Поддерживается подмножество YAML: плоские `ключ: значение` в `meta` и `defaults`, записи в одну строку `- {k: v, ...}` в списках, комментарии `#`. Многострочные значения и вложенность не поддерживаются.

## API

`POST /adjust` принимает JSON:

```json
{
  "reference_points": [{"id": "A", "x": 0, "y": 0}],
  "observations": [
    {"type": "azimuth", "from": "A", "to": "C", "value": 20.556045, "sigma": 0.6},
    {"type": "distance", "from": "A", "to": "C", "value": 854.4004, "sigma": 0.005}
  ],
  "include_trace": false
}
```

Для `angle` обязательно поле `to2` (угол при `from` от луча на `to` до луча на `to2`). Ответ содержит уравненные координаты и точность, невязки, ориентировки станций, `σ₀`, ранг и дефект ранга; при `include_trace: true` — ещё и журнал вычислений (в радианах и метрах, как внутри солвера). Ошибки данных возвращаются с кодом 400 и пояснением.

## Деплой на Render

Приложение — один сервис: FastAPI отдаёт и API, и статический интерфейс из `web/`, поэтому отдельный хостинг для фронтенда не нужен. GitHub Pages не подходит, так как расчёт выполняется на Python (NumPy/SciPy).

1. Код должен лежать в репозитории на GitHub или GitLab.
2. В [Render](https://render.com) нажмите **New → Blueprint** и выберите репозиторий. Render прочитает `render.yaml` и создаст веб-сервис `geo-adjust`.
3. Дождитесь сборки (установка SciPy занимает минуту-две). Адрес сервиса будет вида `https://geo-adjust.onrender.com`.

Дальше каждый `git push` в `main` автоматически запускает новый деплой.

Если вы создаёте сервис вручную (**New → Web Service**), укажите:

| Параметр | Значение |
|---|---|
| Runtime | Python |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn api.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/` |

Версия Python берётся из `.python-version` (сейчас `3.14`). Можно переопределить переменной окружения `PYTHON_VERSION` с полной версией (например `3.13.5`).

На бесплатном плане Render сервис засыпает после периода простоя, и первый запрос после паузы может выполняться заметно дольше обычного.

Быстрая проверка развёрнутого сервиса:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://geo-adjust.onrender.com/
```
